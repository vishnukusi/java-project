A vision pipeline can change without anyone noticing.

The problem

Training images, annotations, the model file and the record of what it predicted can each be altered, swapped or replayed. A tampered or poisoned asset often looks perfectly normal when you open it, and the model may still run.

What SentinelCV does

It checks each layer separately, then combines the results into one report: what was found, which files are affected, how severe it is, how confident the check is, and what to do next.

Five layers, checked in plain terms.

Dataset integrityCOCO and YOLO ZIP archives

Looks for duplicate and near-duplicate images, annotations that are invalid or inconsistent with their images, and images that fail integrity checks.

Model integrityONNX and TorchScript files

Fingerprints the model file and tests how it responds to probe inputs, including trigger-style perturbations, so unexpected behaviour can be flagged.

Inference provenanceImported inference records

Verifies each record’s hashes, its link in the record chain, its signature, nonce, sequence and timestamp, and flags broken chains and replayed records.

Distribution shiftA reference and a new dataset

Compares the two datasets and reports whether the new data differs from the reference in ways that could affect the model.

Assurance reportingJSON, HTML or PDF

Lists findings with severity, confidence, evidence, affected files and a recommended action, so a reviewer can act on them.

From upload to report in four steps.

  1. Choose a scan

    Pick dataset, model, inference or distribution analysis and upload the files.

  2. Checks run locally

    Dataset and model scans run in the background, and you see their real status.

  3. Review findings

    Open each finding for its evidence, affected files and recommended action.

  4. Generate a report

    Export the assessment as JSON, HTML or PDF.

What it can and cannot tell you.

SentinelCV reports evidence. It does not certify that anything is safe.

It can

  • Show you duplicates, invalid annotations and unusual files in a dataset.
  • Flag a model whose file or behaviour raises concerns.
  • Show which inference records fail verification, and why.
  • Show where two datasets differ.

It cannot

  • Prove an asset is safe. No finding means the checks that ran found nothing.
  • Catch every poisoned sample or hidden backdoor. No check can.
  • Tell you where your data came from before you uploaded it.
  • Run semantic ML analysis. Optional local ML analysis is not configured in this build, and the other checks do not depend on it.
  • Repair data or models. It reports and recommends.

Your files stay on your machine.

Offline by design

Uploads, results and reports are stored locally. Models are run locally with ONNX Runtime, and nothing is sent to an outside service for analysis. This page loads no external fonts, scripts or styles.

Built on

Java 21 and Spring Boot, with a local SQLite database. Cryptographic hash and signature checks are done in Java.
